# RavenDB AI Agents

Concepts and the HTTP surface. Client calls: your language's `ai-agents.md`, and `client-docs.md` (Creating AI agents: API).

## Concepts

Three separately licensed features `(license)`: AI agents, embeddings generation, GenAI. Check with `version-gate.md`.

| Piece | What it is |
|---|---|
| AI connection string | One model provider; `modelType: "Chat"` for agents, `"TextEmbeddings"` for embeddings. Settings: `client-docs.md` (AI connection strings). |
| Agent configuration | Stored in the database record. Creating it returns the `identifier` every later call takes. |
| Parameters | Values the caller supplies when a conversation opens; queries use them as `$name`. `sendToModel: false` hides one from the model. |
| Queries | RQL the *server* runs when the model asks. |
| Actions | Tools the model calls and *your app* runs, sending the result back. |
| Sub-agents `(7.2.2+)` | Agents a parent agent calls as tools: `client-docs.md` (Multi-agents). |
| Conversation | A document in `@conversations`. An id prefix ending in `/` or `\|` gets a server-assigned tail; a full id resumes. Each turn returns a change vector for optimistic concurrency. |

**Agents live on the server.** A configuration in code does nothing until the connection string and the agent are PUT, in tests too. A turn against an agent never created fails with `AI Agent '<id>' doesn't exists`.

**Creating an agent replaces one with the same name.** The PUT is create-or-update and, without an `identifier`, derives one from `name`. List the agents first (`GET /databases/{db}/admin/ai/agent`).

**A sub-agent can receive a model-invented value.** A parameter the parent does not pass is generated by the parent's model, so a user or tenant id scoping the sub-agent's queries can name another user. Give such parameters the `ForbidModelGeneration` policy: `client-docs.md` (Multi-agents).

Before writing provider settings, mirror a working connection string from `GET /databases/{db}/admin/connection-strings` with the same `modelType`.

## HTTP endpoints

| Route | Verb | Purpose |
|---|---|---|
| `/databases/{db}/admin/connection-strings` | PUT | Store the AI connection string |
| `/databases/{db}/admin/ai/agent` | PUT | Create/update agent (body = agent configuration); returns `{ Identifier, RaftCommandIndex }` |
| `/databases/{db}/admin/ai/agent?agentId={id}` | GET / DELETE | Read (`{ AiAgents: [...] }`) / delete |
| `/databases/{db}/ai/agent?conversationId={cid}&agentId={id}[&changeVector=..][&streaming=true&streamPropertyPath=..]` | POST | Run one conversation turn |

Run-turn body / response:

```json
{ "UserPrompt": [{ "Type": "text", "Text": "..." }],
  "ActionResponses": [{ "ToolId": "...", "Content": "json string" }],
  "ArtificialActions": null,
  "CreationOptions": { "Parameters": { "clientId": { "Value": "clients/1-A", "SendToModel": true } },
                       "ExpirationInSec": null, "MaxModelIterationsPerCall": null } }
```

```json
{ "ConversationId": "...", "ChangeVector": "...",
  "Response": { "your output schema": "..." },
  "ActionRequests": [{ "Name": "...", "ToolId": "...", "Arguments": "json string" }],
  "Usage": {}, "TotalUsage": {}, "Elapsed": "00:00:02" }
```

Non-empty `ActionRequests`: run each action, then POST again with matching `ActionResponses` and no new prompt. With `streaming=true` the response is line-delimited: JSON-string chunks of the streamed property, then one final `{...}` result object.

## Embeddings generation over HTTP

Setup: `client-docs.md` (Embeddings generation task). Querying: `rql-docs.md` (Vector search).

PUT `/databases/{db}/admin/etl` needs `"EtlType": "EmbeddingsGeneration"`. Without it: `"ETL configuration must have EtlType field"`; a wrong value: `"Unknown ETL type"`. `"GenAi"` is a different feature on the same endpoint, licensed by `HasGenAi`: a 402 naming Gen AI means the wrong type, not a missing `HasEmbeddingsGeneration`.

Working apps: `samples.md` (`samples-fit`, `samples-verity`).
